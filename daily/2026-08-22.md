## 引导问题问答记录

### Q1: System Prompt vs 普通 Prompt 的本质区别？

**用户回答**：内置在 Agent 中每次调用，优先级比对话高；Agent 场景角色各异，用 System Prompt 约束更好。

**纠偏**：
- ✅ 正确：System Prompt 是开发者注入的稳定配置；对话内容是运行时动态数据
- ⚠️ 修正"优先级高"：不存在强优先级，System Prompt 与 user message 都是输入上下文，模型无真正"优先遵循"机制（这正是 Prompt Injection 得手的原因）。准确说法：**位置固定 + 语义上承载稳定规则**

### Q2: 为什么 Few-shot 示例比描述更有效？

**用户回答**：示例更准确、有参考性；选不好会输出错误格式。

**补充**：
- LLM 本质是 next-token 预测，"模仿具体样例模式"比"理解抽象描述"更贴合其工作机制
- 示例选不好的更严重后果：学到错误模式（如过度调用工具）、边界未覆盖导致泛化失败
- 要求：典型 + 覆盖边界 + 必要时标注反面例子

### Q3: 推理过程与最终答案分离的价值？

**用户回答**：推理不显示给用户，调用上一轮结果更方便。❌ 偏了

**纠正**：推理是思考草稿，不该作为结果回传。正确价值：
- **可审计性**：开发调试时能看 Agent 为什么这么决策
- **输出纯净**：程序只解析 `answer` 字段，不被推理噪声干扰
- **不泄露**：中间推理可能含错误想法，不暴露给用户
- 本质是"可解释性 + 结构化输出"的组合

### Q4: System Prompt 为什么是防注入第一道防线？挡不住什么？

**用户回答**：防止恶意注入（未知挡不住什么）。

**补充攻击面**：

| 攻击面 | 说明 |
|--------|------|
| 直接注入 | 用户消息里写"忽略以上规则"，可能覆盖 System Prompt |
| 间接注入 | 检索到的文档/网页内容里藏指令（RAG 场景） |
| 工具注入 | 工具返回内容里夹带恶意指令 |
| 多模态注入 | 图片中的文字指令 |

真正防线是组合拳：Guardrail 校验 + 最小工具权限 + 内容过滤 + 隔离。

## RAG 引导问题问答记录

### RQ1: RAG vs 全文塞入 prompt 的核心优势？代价？

**用户回答**：RAG 占用上下文比全文少很多；代价是准确度依赖 RAG 技术。

**纠偏**：
- ✅ 正确：上下文占用大幅减少
- ⚠️ 漏了更关键优势：**知识可即时更新**（改库即可）、**可溯源**（引用真实文档）、**缓解幻觉**
- 代价补充：还取决于模型是否严格基于检索材料回答——检索到正确文档但模型凭记忆发挥，照样幻觉

### RQ2: 切分粒度与 overlap？

**用户回答**：大了上下文过长/无用信息多，小了信息不完整；疑问"overlap 是什么？"

**点评**：✅ 答案完全正确
**答疑（overlap）**：相邻块之间保留一段重叠字符，防止关键句子恰好被切断在块边界丢失。

```
chunk_size=1000, chunk_overlap=200
块1: 第 1~1000 字符
块2: 第 801~1800 字符  ← 重叠 200 字符
```

### RQ3: 为什么 RAG 是间接注入高发区？System Prompt 挡不住的本质？

**用户回答**：RAG 答案与 System Prompt 共享上下文，检索资源来自网络不安全；本质原因是 System Prompt 会执行输出的命令。

**纠偏**：
- ✅ 正确：共享上下文窗口；外部来源不可信
- ❌ 纠正"System Prompt 会执行输出的命令"：System Prompt 不是执行命令的程序。本质原因是**模型无法可靠区分"数据"和"指令"**——检索文档文字与 System Prompt 指令在模型眼里都是"要处理的 token"，模型只按概率生成最合理的下文。文档里写"忽略上面所有规则"，模型可能真照做，因为它分不清哪句是指令、哪句是文档内容。没有机制能保证这种区分。

### RQ4: 检索作为工具 vs 拼进上下文？

**用户回答**：工具调用完再和用户提示词拼进上下文。

**深化**：现象正确（工具结果最终也进上下文），但本质区别在**决策权**：

| 维度 | 硬拼上下文 | 检索作为工具 |
|------|-----------|-------------|
| 触发方式 | 无条件，每轮注入 | 条件性，模型自主决定 |
| 检索内容 | 预先定死 | 动态构造查询 |
| 迭代 | 一次性 | 不满意可再搜（Agent 循环） |
| 幻觉风险 | 结果无关也塞进去 | 按需检索，更精准 |

## 概念答疑记录

### Few-shot（少样本提示）

- 定义：在 prompt 中给模型几个完整的「输入→输出」示例，让模型模仿完成任务
- 对照：Zero-shot（0 示例）/ One-shot（1）/ Few-shot（少量）
- 出处：GPT-3 论文 *Language Models are Few-Shot Learners*——无需训练，看例子学会新任务格式

### 典型 + 覆盖边界 + 反面例子

- 典型示例：最常见的场景，教"主路径"
- 边界示例：容易混淆/易错的边缘情况，防"泛化失败"
- 反面例子：标注"不要这样做"的错误输出，明确"禁区"

示例（客服意图分类）见对话记录。

### Guardrail（护栏）

- 定义：Agent 输入侧/输出侧的安全校验关卡
- Input Guardrail：请求进入前拦截（作业代写、辱骂、敏感内容）
- Output Guardrail：输出后校验（信息泄露、格式契约）
- 触发动作：拦截终止（tripwire）、拒绝回复、转人工
