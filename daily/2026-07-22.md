### ReAct Agent 实践（项目一代码走读）

- 逐层读懂了 project-01-react-agent 的 159 行代码：
  - `_system_prompt()` — 告诉 LLM 可用的工具和输出格式
  - `_call_llm()` — 发 HTTP 请求到 DeepSeek API
  - `_parse_output()` — 正则从 LLM 文本中抠出 Thought/Action/Action Input/Final Answer
  - `run()` — 核心 loop：调 LLM → 解析 → 执行工具 → 注入 Observation → 循环
- 理解了 Agent 的本质：LLM 只负责"思考+决策"（输出文本），本地代码负责"执行"（调工具）
- 对比了原型版 Agent 和生产级 Agent 的区别：正则 vs Function Calling、无错误处理 vs 重试机制、print vs 流式输出、硬编码工具 vs 插件化、串行 vs 并行、命令行 vs HTTP API + WebSocket
- 理解了 WebSocket 的作用：把 Agent 的内部推理过程"直播"给前端，不是等跑完才返回

### MCP Server 实践（项目二代码走读）

- 逐层读懂了 project-02-mcp-server 的 269 行代码：
  - **Layer 1**：3 个纯函数（`tool_get_time`、`tool_calculate`、`tool_word_count`）— 真正干活的代码
  - **Layer 2**：6 个 MCP 装饰器 — `list_tools`/`call_tool`（工具）、`list_resources`/`read_resource`（资源）、`list_prompts`/`get_prompt`（提示词模板）
  - **Layer 3**：`stdio_server()` — 通过 stdin/stdout 与 MCP Client 通信
- 理解了 MCP 的完整交互流程：Client 发 `tools/list` → Server 返回工具列表 → Client 发 `tools/call` → Server 执行并返回结果
- 对比了 MCP Server 和 ReAct Agent 的本质差异：Agent 是闭环（决策+执行一体），MCP Server 是开环（只管提供服务，决策由 Client 做）

### MCP 传输层：stdio vs HTTP SSE

- **stdio（本地模式）**：Client 启动子进程 → 通过 stdin/stdout 通信 → 用完即走。适合本地工具和开发调试
- **HTTP + SSE（网络模式）**：Server 独立运行监听端口 → Client 通过 HTTP 连接 → SSE 推送响应 → 常驻服务。适合团队共享
- 对应配置文件差异：本地用 `command` 字段，网络用 `url` 字段

## 心得体会

- Harness Engineering 是整个 Agent 学习的"骨架"——理解了这个，再学任何具体框架都能看到它们共通的模式
- MCP 协议的标准化思路很前瞻，类比 USB-C 很好理解
- Claude Code 的极简设计（文件系统 + Shell 即是 Agent 界面）值得深思
- ReAct 的 Thought-Action-Observation 循环看似简单，但它是所有现代 AI Agent 的核心骨架——Harness Engineering 中的 agent loop 其实就是 ReAct 的工程化实现
- 用中文教程学习英文论文是高效的方式：先建立概念框架（Prompt Engineering Guide 中文版），再深入代码实现（LangChain ReAct）
- ReAct Agent 和生产级 Agent 的对比很有启发——核心 loop 一模一样，但每个环节都有加固空间
- MCP 框架的设计很精妙：写 3 个纯函数 + 注册 6 个装饰器 + 1 行启动代码 → 任何 MCP Client 都能发现和调用。一次编写，多处复用
- 从理论到实践的价值巨大：写 ReAct Agent 时，发现 agent loop 就是一个 while 循环 + 正则解析 + 工具调用——之前觉得玄乎的概念瞬间变实了
- 今天的学习量较大但收获很多，从理论基础到具体工具形成了一个较为完整的 Agent 知识闭环
