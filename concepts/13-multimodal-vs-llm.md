# 多模态模型 vs 大语言模型

---

**更新时间**：2026-08-15
**所属阶段**：阶段一 - 基础认知（补充）
**掌握程度**：🔵 理解

---

## 概念定义

大语言模型（LLM）只处理**离散的文本 token**；多模态模型能同时处理**文本、图像、音频、视频等连续信号**。两者的本质区别在于：底层信号是"离散符号"还是"连续信号"。

一句话：**多模态 = 给 LLM 加一个"翻译器"，把图像/音频翻译成 LLM 认识的向量。**

## 本质区别

| 维度 | 大语言模型（LLM） | 多模态模型 |
|------|------------------|-----------|
| 输入 | 文本（离散 token） | 文本 + 图像 + 音频 + 视频 |
| 输出 | 文本 | 文本 + 图像 + 音频 |
| 底层信号 | 离散（token ID 序列） | 连续（像素值、波形采样点） |

**根本矛盾**：LLM 的 Transformer 只能吃"一串整数 token"，而图像是"一张连续像素矩阵"、音频是"一段连续波形"。两者在数学上不是一种东西，所以多模态的核心难点是——**怎么把连续信号变成 LLM 认识的离散 token**。

## 多模态的实现方式：核心思想是"对齐"

所有主流方案都在做同一件事：**把视觉/音频编码成 LLM embedding 空间里的向量，再喂给 LLM**。有三条路线：

### 路线 1：Encoder + Adapter（最主流，如 LLaVA、Qwen-VL）

```
图像 → 视觉编码器(ViT/CLIP) → 投影层(Adapter) → LLM
       [连续像素]              [连续向量]         [对齐到文本空间]
```

1. 视觉编码器把图变成一串 feature 向量
2. Adapter（一个简单的线性层/MLP）把这些向量"翻译"到文本 token 的空间
3. 最后拼在文本 token 后面一起输入 LLM

### 路线 2：原生多模态 tokenizer（如 Gemini、GPT-4o 的技术路线）

直接把图像离散化成"视觉 token"，和文本 token 混在同一序列里端到端训练——更彻底，但成本极高。

### 路线 3：输出侧生成图像

LLM 负责"理解 + 决定画什么"，输出文本描述，再交给扩散模型（Stable Diffusion / DALL-E）生成像素。这是**理解与生成分离**的方案。

## 为什么主流都依赖大语言模型

1. **LLM 已经积累了最强能力**：海量文本训练让 LLM 掌握了语言理解、逻辑推理、世界知识、指令遵循。这些是"通用智能"的核心，图像模型自己练不出来。
2. **迁移成本极低**：在强大 LLM 上加一个 Adapter 就能获得视觉能力，比从头训练一个"原生多模态模型"便宜几个数量级。
3. **推理能力可跨模态迁移**：文本里学会的"对比、推理、规划"能力，对齐后能直接用在视觉任务上（比如看图解数学题）。

这就是为什么 GPT-4V、Gemini、Qwen-VL、Claude 全都是"LLM 为核心 + 多模态输入扩展"的架构。

## 大语言模型能向多模态转换吗？——能，而且这就是主流做法

**"向多模态转换"不是替换 LLM 的核心，而是给它扩展输入接口。**

转换路径就是路线 1，三步：

```
1. 冻结/训练一个视觉编码器（把像素变向量）
2. 加一个 Adapter 投影层（把视觉向量对齐到 LLM 的 embedding 空间）
3. 用"图像-文本"对做继续训练（对齐 + 微调）
```

LLM 的 Transformer 主干、知识、推理能力**全部保留**，只是多了一个新的"感官"。

**为什么不能直接转换？** 因为纯文本训练的 LLM，其 embedding 空间里根本没有"图像"的坐标——直接把像素塞进去，LLM 看到的就是一堆无意义乱码。所以必须：
- 先有一个视觉编码器（它懂图像）
- 再用 Adapter 做"翻译"（把图像信息映射到 LLM 能理解的语义空间）

**类比**：LLM 是一个只学过中文的人，你想让它也会英文。你不是把它的大脑重造一遍，而是给它一个"英文→中文翻译器"，再让它练习双语对照。翻译器（Adapter）是关键，大脑（LLM）不用换。

## 与其他概念的关系

- **前置概念**：Transformer 架构、Tokenizer（文本如何变成 token）
- **后置概念**：多模态 Agent（视觉 Agent，能看图操作界面）、VLM（Vision-Language Model）
- **相关概念**：[Function Calling](./05-function-calling.md)（多模态模型同样支持工具调用）、[Harness Engineering](./01-harness-engineering.md)（多模态能力通过 API 接入 Agent）

## 常见误区

- **误区一："多模态模型是全新的架构"**：主流多模态模型的内核仍然是 Transformer + LLM，只是加了视觉编码器和 Adapter。核心推理引擎没换。
- **误区二："多模态 = 能生成图像"**：现在说的"多模态大模型"（GPT-4o、Gemini）大多是**理解侧多模态**（能看图、识别图），但**生成侧**（能画图）往往还是靠外挂扩散模型。真正"原生输入输出都多模态"的模型还在早期阶段。
- **误区三："Adapter 训练会毁掉 LLM 的文本能力"**：现代方案通常用 LoRA 等轻量微调或冻结 LLM 主干，只训练 Adapter，尽量保留原有文本能力。
