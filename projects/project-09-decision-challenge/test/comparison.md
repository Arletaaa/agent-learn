# 对比实验：有 Skill vs 无 Skill（2026-08-23）

## 实验设定

- **同一决策**：HD490 Pro vs HD660S2 谁更适合听 ACG（`prompt.md` 为用户原始倾向陈述）
- **版本 A（有 Skill）**：加载 `SKILL.md` v2，按三阶段质询执行 → `with-skill.md`
- **版本 B（无 Skill）**：不加载 Skill，直接回答 → `no-skill.md`
- **测量口径**：字符数（精确）；token 按中文 ≈ 0.75 token/字符 估算（实际 tokenizer 有出入）；时间以输出字符数为生成耗时代理（生成耗时 ≈ 输出 token 数，会话内无墙钟可测）

## 实测数据

| 文件 | 字符数 | 估算 token |
|------|--------|-----------|
| `prompt.md`（输入） | 71 | ≈ 53 |
| `no-skill.md`（输出 B） | 176 | ≈ 132 |
| `with-skill.md`（输出 A） | 462 | ≈ 346 |
| `SKILL.md` v2（加载开销） | 1381 | ≈ 1036 |

## 成本对比

| 指标 | 无 Skill | 有 Skill（v2） | 倍数 |
|------|---------|---------------|------|
| 首次单次成本（输入+输出） | 71+176 ≈ 247 字符 ≈ **185 token** | 1381+71+462 ≈ 1914 字符 ≈ **1435 token** | ≈ 7.8× |
| 同会话第 2 次起（增量） | prompt+输出 ≈ 247 字符/次 | 仅输出 ≈ 462 字符/次（SKILL.md 已加载摊销） | ≈ 1.9× |
| 生成时间（输出代理） | 1× | ≈ 2.6×（输出 462/176） | ≈ 2.6× |

**解读**：Skill 的成本大头是**首次加载**（SKILL.md ≈ 1036 token，占 72%）。加载一次后在同会话内摊销，后续决策的边际成本只剩"结构化输出比朴素回答长"的差价（1.9×）。用这笔差价换来的是每次决策的质量保证——且 Skill 文件可跨会话、跨用户复用。

## 结果质量对比

| 维度 | 无 Skill | 有 Skill |
|------|---------|---------|
| 对用户倾向的态度 | ❌ 完全顺着："你的判断有道理" | ✅ 反驳**论证前提**（"660S2 不适合人声"与主流听感相悖） |
| 对错误前提的处理 | ❌ 强化它（"暖糊调音不适合 ACG"） | ✅ 拆穿它（暖≠糊，暖声压齿音适配干冷刺录音） |
| 结构 | 无，一段式 | 三阶段（反方/正方/裁判） |
| 不确定性 | ❌ 无置信度、无未知变量 | ✅ 明说"不确定（中）"，点名最大未知（曲库构成） |
| 可证伪性 | ❌ 给确定建议"值得入手" | ✅ 给反转条件（循环最多的是女声曲 → 反转选 660S2） |
| 有效信息（正确事实） | 两者都识别了 490 Pro 解析/声场/好推 | 同左 |

**关键结论**：两个版本在"知识"上没有差异（都知道 490 Pro 解析强声场大）——差异在**敢不敢反驳 + 诚不诚实标注不确定**。无 Skill 时模型不是不知道反方论点，而是倾向输出让用户舒服的答案；Skill 用强制结构把模型**已有的**批判能力"逼"出来。这也说明：反谄媚不是"更聪明的模型"问题，是"输出约束"问题。

## 方法论局限（诚实标注）

1. **基线被污染**：会话内模拟，无 Skill 版本已见过反方论点，真实冷启动的朴素回答可能不同
2. **无墙钟**：时间用输出字符数作线性代理，非真实延迟
3. **token 为估算**：中文 ≈0.75 token/字符，实际 tokenizer 有出入；严谨测量应读 API 响应的 `usage` 字段
4. **单次运行**：非多轮统计，结论方向可信、数值仅供参考
   → 严谨评估（同模型多 trial + TTFT/延迟/usage 统计）正是 roadmap **阶段五「Agent 评估指标与方法」**的内容
